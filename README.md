# 跨境单证合规校验

> 一票跨境货物的多份单证，自动交叉比对——把"报关环节才发现对不上"提前到"提交前就看见"。

同一票货物往往涉及商业发票、装箱单、提单、报关单等多份单证。它们由不同主体分别填写、格式与语言不一，人工逐份核对成本高；而单证之间的矛盾（件数对不上、毛重不一致、HS 编码归类存疑）常常拖到报关或放货环节才暴露，直接导致滞港、罚款乃至退运。

本项目读取一票货物的多份单证，抽取关键字段，**交叉比对文件之间的一致性**，并依据目的国规则提示证书缺失或归类风险。系统不替人下结论——它只定位矛盾、给出可追溯的依据，把最终判断留给负责合规的人。

**在线 Demo**：https://hackathon-demo.ychome.net

## 功能

| 能力 | 说明 |
|---|---|
| 单证解析 | 解析 PDF / 图片格式的单证，输出结构化字段 |
| 字段抽取 | 抽取 HS 编码、件数、毛重、金额等关键字段，并归一为可比较的值 |
| 交叉比对 | 在同一票货物的多份单证间比对相同字段，标记不一致项并定位到具体文件与原始值 |
| 合规提示 | 依据目的国规则，提示证书缺失、归类待复核等事项，附规则编号与触发字段 |
| 结果呈现 | 上传 / 差异 / 报告三个工作界面，另附模型评测看板 |

**系统明确不做的事**：不判定哪份文件的值正确，不给出海关归类的最终结论，不代替人工完成合规审查。未经规则校验的提示会单独分组，与规则命中的提示区分开。

## 设计原则

三条约束贯穿数据结构与界面实现，是这个项目区别于"能跑就行"的 demo 的地方：

1. **状态必须可区分。** "本就不适用"（NOT_IN_DOC）、"应当存在却没抽到"（MISSING_IN_DOC）、"规则未覆盖"（NOT_CHECKED）是三种不同情况，**任何一种都不能被渲染成"校验通过"**。
2. **失败必须显式。** 处理失败绝不返回空结果——否则界面会把它显示成"检查完成，没有问题"。
3. **不伪造数据。** 缺失的可信度、未运行的评测、未提供的定位信息一律如实留空，不用默认值填充，也不为了页面好看而编一个数字。

## 快速开始

前端是一个可独立运行的应用，开发期默认读取内置示例数据，无需后端即可体验完整流程。

```sh
cd web
npm install
npm run dev        # 开发服务器（默认 http://localhost:5173）
```

产出与校验：

```sh
cd web && npm run build     # 构建到 web/dist/

# 仓库根目录：校验示例数据是否符合数据契约
npm install
npm run validate
```

切换到真实后端：修改 `web/src/api/config.js` 中的 `USE_MOCK`，并在 `worker/index.js` 中打开 `/api/` 代理段、填入后端地址。

## 技术栈

- **前端**：Vue 3（`<script setup>`）+ Vite 6，自研设计系统（OKLCH 色彩、CSS 变量 token），无 UI 组件库 / 路由 / 状态管理依赖
- **边缘部署**：Cloudflare Workers + Assets 绑定，托管静态前端并预留 `/api/` 反向代理
- **契约校验**：JSON Schema + AJV，含结构与跨字段自洽两层校验

刻意保持轻量：整个前端打包后 JS 约 100 KB（gzip 约 39 KB），零重型依赖。

## 架构

```
┌─────────────┐   HTTP    ┌──────────────────┐   /api/   ┌─────────┐
│  Vue 3 前端  │ ────────► │ Cloudflare Worker │ ────────► │  后端    │
│ (web/dist)  │ ◄──────── │  静态托管 + 代理   │ ◄──────── │ (待接入) │
└─────────────┘           └──────────────────┘           └─────────┘
       ▲
       │ 以 docs/schema/check-task.schema.json 为唯一事实来源的数据契约
```

前端不直接 `fetch`，统一走 `web/src/api/index.js`；状态文案集中在 `web/src/api/labels.js`。请求层内置网络/5xx 指数退避重试、慢轮询提示，以及全局错误边界防止白屏。

## 数据契约

前后端之间的数据格式以 [`docs/schema/check-task.schema.json`](docs/schema/check-task.schema.json) 为**唯一事实来源**，[`docs/数据契约.md`](docs/数据契约.md) 是其可读版本，两者保持一致。

`npm run validate` 校验两个层面：

- **结构**：字段名、类型、枚举取值、必填项；
- **自洽**：`summary` 中的计数须与数组实际长度一致；并含跨字段约束以防静默错误（如 `NOT_CHECKED` 必须给出未校验原因、`CONFLICT` 至少包含两个不同值）。

后端就绪后，把真实返回交给校验脚本即可判定是否符合契约。

