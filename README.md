# 跨境物流单证智能转换与合规校验系统

面向跨境出口与货代业务的多单证交叉核对与合规辅助工具。将同一票货物的商业发票（Commercial Invoice）、装箱单（Packing List）、提单（Bill of Lading）等单证集中上传，系统自动完成字段抽取与单位归一化，逐项比对多份文件之间的数值差异与缺失，并结合目的国规则给出待复核提示与可归档报告。

**在线体验：[hackathon.ychome.net](https://hackathon.ychome.net)** · **[示例演示模式](https://hackathon.ychome.net/?mock=1)** · **[API 文档](https://hackathon.ychome.net/docs)**

---

## 核心能力

| 模块 | 功能说明 | 适用边界 |
|---|---|---|
| **多源单证解析** | 支持文本层 PDF 直读、标准 `UN/EDIFACT INVOIC:D:96A:UN` 报文解析，以及图片、扫描件 PDF 的版面识别与字段抽取（基于 PaddleOCR-VL-1.6）；完整保留原始读数与页码定位。 | 无法识别或版式异常时显式标记，不伪造置信度、页码或坐标；`DESADV`、多报文信封或 X12 等其他 EDI 格式如实标记为不支持。 |
| **多单证交叉比对** | 覆盖件数、毛重、净重、体积、数量、单价、总价、币种、HS 编码等核心字段；支持多商品行按货号自动分组对齐，不受各单证行序差异影响。 | 严格区分「不一致」「部分缺失」「未校验」与「仅一份文件提供」；无法可靠对齐的商品行单独作为单文件证据留存，不猜测对应关系。 |
| **目的国合规提示** | 根据目的国与商品编码匹配关注事项（当前内置美、德、荷、法、英五国演示规则），将规则依据与模型建议分开呈现。 | 内置规则仅作业务复核参考，不替代正式法律适用核实或海关合规结论。 |
| **原件对照与修正** | 差异页支持表格与并排对照双视图，可在页面右侧抽屉就地预览单证原件并跳转对应页码；支持人工修正有效抽取值并触发重算。 | 修正操作生成派生任务并记录前后审计，原始读数与原件证据保持不变。 |
| **可存档检查报告** | 结论先行，汇总不一致、缺失与风险提示；支持导出自包含 HTML 报告（可离线浏览或通过浏览器打印为 PDF）及完整归档 JSON。 | `COMPLETED` 仅代表处理流程结束，`MATCH` 仅代表参与比对的值一致；任何未校验、缺失或解析失败均不呈现为“通过”。 |
| **系统评测看板** | 独立展示固定数据集上的字段抽取与冲突检出实测表现（精确率、召回率、F1 与 TP/FP/FN 计数），支持按输入通道与批次切换查验。 | 评测数据由离线基准脚本生成并附带 SHA-256 复现指纹，日常单证上传不触发跑分。 |

## 快速体验

线上服务已部署完整前后端环境，打开即用，无需本地配置：

1. **真实单证检查**：访问 **[hackathon.ychome.net](https://hackathon.ychome.net)**（默认连接真实后端），拖入同一票货物的多份单证（PDF / PNG / JPG / WEBP），选择目的国后点击「开始检查」。仓库 [`backend/samples/`](backend/samples/) 提供了多组可直接用于验证的合成单证样例。
2. **内置场景演示**：访问 **[示例演示模式（`?mock=1`）](https://hackathon.ychome.net/?mock=1)**，无需准备文件，可在首页底部点击任一预设场景（单品名冲突、多品名分组、部分文件失败、EDI 报文等），直接体验从上传进度、差异定位到检查报告的完整流程。访问 `?mock=0` 即可切回真实后端模式。

## 系统架构

```text
浏览器 ──► HTTPS / Nginx
             ├─ /            ──► 前端单页应用（Vue 3 + Vite）
             └─ /api/v1/...  ──► 后端服务（FastAPI / Python 3.12）
                                   ├─ 文档解析：文本层 PDF 直读 / PaddleOCR-VL-1.6
                                   ├─ 核对引擎：字段抽取、单位归一、多品名行对齐、交叉比对
                                   ├─ 合规引擎：目的国规则匹配、官方来源目录与变更监测
                                   └─ 持久化层：SQLite 任务存储、修正审计与评测档案
```

## 本地运行与构建

### 环境要求

- **前端**：Node.js 20+
- **后端**：Python 3.12+

### 启动前端

在仓库根目录下安装依赖并启动开发服务器：

```sh
npm ci
npm --prefix web ci
npm --prefix web run dev
```

启动后访问 `http://localhost:5173/?mock=1` 即可使用内置示例数据体验全部界面功能。

### 连接本地后端

按 [后端说明](backend/README.md) 启动本地 FastAPI 服务（默认监听 `127.0.0.1:8000`）后，通过环境变量启用开发代理：

```sh
VITE_PROXY_API=http://127.0.0.1:8000 npm --prefix web run dev
```

> Windows PowerShell 可先执行 `$env:VITE_PROXY_API = 'http://127.0.0.1:8000'`，再运行 `npm --prefix web run dev`。若浏览器此前停留在示例模式，访问 `http://localhost:5173/?mock=0` 切回真实后端。

### 校验与测试

```sh
npm run validate               # 校验 JSON Schema 与契约示例数据
node --test tests/*.test.mjs   # 运行前端与报告生成单元测试
npm --prefix web run build     # 构建前端生产产物
```
