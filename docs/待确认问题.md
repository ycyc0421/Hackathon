# 系统能力边界与待扩展事项

本文档汇总当前系统的设计边界、已知限制及后续扩展方向。已上线能力总览见 [系统现状与演进规划](项目现状与计划.md)。

---

## 一、已落地的工程边界

- **同源整站与任务持久化**：前后端通过 `https://hackathon.ychome.net` 同源提供服务；任务进度、抽取证据、人工修正审计与系统评测档案均持久化于跨版本共享的 SQLite 与数据目录。
- **多源解析与真实探针**：支持文本层 PDF 直读、图片与扫描 PDF 的本地 `PaddleOCR-VL-1.6` 识别，以及 `hackathon-trade-json-v1` 结构化贸易 JSON 输入。
- **单票多品名与原件追溯**：支持多商品行按货号/品名自动对齐与分组比对，差异页支持在页面右侧抽屉就地预览原件并跳转对应页码。
- **结构化报告与派生修正**：基于报告契约 v2 支持导出自包含 HTML 报告（可打印为 PDF）与完整归档 JSON，支持对有效抽取值提交人工修正并触发派生任务重算。
- **固定数据集系统评测**：已完成 `synthetic-hackathon-v2` 数据集在文本 PDF 通道与扫描 OCR 通道上的离线跑分与看板接入。

---

## 二、当前能力限制与后续扩展条件

| 领域 | 当前边界 | 后续扩展条件 |
|---|---|---|
| **标准 EDIFACT 报文解析** | 前端已支持 `.edi` 文件上传、纯文本安全预览与 6 个合成演示场景；真实后端对 `.edi` 如实返回 `UNSUPPORTED`，尚未启用服务端 EDIFACT 解析。 | 接入 `INVOIC` / `DESADV` 语法解析器并通过 [`backend/samples/edi/`](../backend/samples/edi/) 23 份正负样本端到端回归。 |
| **目的国合规规则核实** | 内置美、德、荷、法、英五国规则并已接入 5 个官方法规来源的定时更新监测，但所有规则均标为 `UNVERIFIED`（演示性质），不作为正式法律或报关结论。 | 对法规条款、适用商品范围及豁免条件完成人工法务核实后，方可按版本启用已核实标识。 |
| **单证类型与字段覆盖** | 必需/可选/不适用字段规则表当前聚焦商业发票、装箱单与提单的核心 11 项字段；形式发票等归入 `OTHER`。 | 扩充报关单、原产地证、保险单等单证类型的独立字段规则表与地址结构化比对。 |
| **评测数据集多样性** | 现有评测分数基于 `synthetic-hackathon-v2` 合成数据集（已用于开发期回归），不代表真实复杂商业版式的泛化准确率。 | 引入脱敏授权的多语种、多版式真实业务单证，扩充分通道评测基准。 |
| **并发容量与长任务调度** | 8 GiB 内存配额下模型采用单并发推理，API 最多同时接纳 4 票任务（超出返回 HTTP 429），重启时未完成任务标记为 `FAILED`。 | 如需更高吞吐量，需扩充 GPU/CPU 算力节点并引入持久化外部任务队列。 |
