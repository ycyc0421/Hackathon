# 项目现状与开发计划

**核对日期：2026-10-12。代码与部署基线：`76ffb55`。** 本文是有日期的交付快照，不承诺后续主分支或服务器永远停留在此版本。变更后应更新本文，线上状态仍以部署记录为准。本分支另含下述待发布改动，不能提前计为已上线。

## 已交付

- 统一入口 `https://hackathon.ychome.net`，前端与 API 同源；旧 Demo、旧后端入口跳转到统一域名。
- 上传、差异、报告和评测四页可用；默认示例模式，真实后端通过 `?mock=0` 或顶栏切换。

## 验证证据

统一域名版本的 [部署运行 38202061980](https://github.com/ycyc0421/Hackathon/actions/runs/38202061980) 成功，覆盖三组文本 PDF、11 号 PNG、由同样 PNG 无损封装的无文本层扫描 PDF、首页资源和返回契约。OCR 检查要求所有文件成功、4 个商品保留并检出预期品名颜色冲突。

四核配置的隔离样例实跑中，3 张 PNG 首次处理约 74 秒，随后 3 份扫描 PDF 约 49 秒；此前正式服务样例验证后进程所在服务的内存峰值约 4.3 GiB。不同轮次包含模型初始化、缓存和运行环境差异，**这些不是时延保证、容量上限或准确率指标**。更大图片、多页文件及并发负载尚需单独验证。

## 建议开发顺序

| 顺序 | 工作 | 协作 | 完成依据 |
|---|---|---|---|
| 1 | 存储接入与迁移评审 | C、F；D 核对展示 | 证据和商品关联不丢失，重复迁移不覆盖任务，重启状态明确，回退可读 |

上述是建议顺序，不是替团队承诺的截止时间。原交付节点及其来源见[项目要求](项目要求.md)；未决事项见[待确认问题](待确认问题.md)。

## 后续变更流程

需求与边界确认 → 分支实现 → 相应模块回归与契约校验 → PR 审查 → 合并 → main CI → 自动部署 → 公网探针 → 浏览器验收。小型独立修复可 squash 合并，保持提交主题清晰。

每次上线记录提交、部署运行、输入和实际结果。发布前避免仍有处理中的演示任务；数据库变更另做数据备份与兼容核验，代码回退不会自动回滚数据。
