# 系统评测与持久化机制

系统评测模块用于衡量并展示后端流水线在固定基准数据集上的实测表现。评测看板（`#/eval`）直接读取已持久化的评测结果档案，日常单证上传不会触发跑分。

---

## 1. 数据集与评测范围

当前基准数据集为 `synthetic-hackathon-v2`：

- **规模与划分**：共 100 票货物（划分为 `train` 70 票、`validation` 15 票、`test` 15 票），包含 300 份文本层 PDF（每票 3 份单证）、30 张派生 PNG 图片与 30 份派生无文本层扫描 PDF。
- **指纹校验**：每份输入文件均通过 `input_sha256.json` 校验完整性；运行评测时对全部输入与金标清单计算整体 SHA-256 指纹（`scope.dataset_sha256`）并写入结果。
- **适用边界**：
  - 文本原件与扫描变体对应同一批业务货票，按输入通道（文本 PDF 通道 / 扫描 OCR 通道）分批独立评测与展示，不合并相加。
  - 该数据集曾用于开发期回归验证，即使单独抽取 `test` 划分，结果仍作为开发回归基线参考，不宣称为盲测泛化准确率。
  - 目的国规则尚未经过正式法律适用核实，因此当前仅对**字段抽取（`field_extraction`）**与**冲突检出（`conflict_detection`）**两项指标计分，**风险提示（`risk_hint`）**不计分。

---

## 2. 计分口径

1. **字段抽取（`field_extraction`）**：
   - 以 `(文件名, 商品货号, 字段键, 归一值, 单位)` 构成事实五元组，按多重集合统计微平均 `TP`、`FP`、`FN`。
   - 金标存在而未抽出计 `FN`；系统多抽出计 `FP`；抽取值或单位不符同时计 1 次 `FP` 与 1 次 `FN`；同一事实重复输出计 `FP`。
   - 仅评估金标定义的字段键，但不按当前已实现字段缩减金标分母（尚未覆盖的字段如实计入 `FN`）。
2. **值归一化与商品关联**：
   - 字符串仅做 Unicode NFKC、大小写与连续空白折叠；数值按精确十进制比对，不使用容差掩盖金额或数量误差。
   - 商品行严格按输出的商品货号（`item_code`）与金标关联；缺少行级货号或货号重复导致无法唯一关联时视为未对齐，绝不按行号位置或显示名猜测。
3. **冲突检出（`conflict_detection`）**：
   - 以 `(商品货号, 字段键)` 标识跨文件 `CONFLICT`，按微平均统计 `TP`、`FP`、`FN`。
   - 漏检、标记为 `NOT_CHECKED` 或任务失败均计入 `FN`；内部风险或缺失提示不充当冲突检出。
4. **指标换算公式**：
   - $\text{Precision} = \frac{TP}{TP + FP}$，$\text{Recall} = \frac{TP}{TP + FN}$，$\text{F1} = \frac{2TP}{2TP + FP + FN}$。
   - 分母为零时对应指标返回 `null`（前端显示为 `—`），绝不补为 `100%`。
   - 错误分类（`error_breakdown`）由计数推导，各类别之间可能存在交集，不可直接相加作为错误总数。

## 3. 离线运行评测

在已安装后端依赖、且 Git 工作区干净无未提交改动的环境下执行：

```sh
# 1. 文本层 PDF 通道评测
python backend/tools/evaluate_dataset.py \
  --dataset <数据集根目录> \
  --out <证据输出目录> \
  --split all \
  --input-kind text

# 2. 扫描件 / 图片 OCR 通道评测（需本地 VL 服务就绪）
PADDLE_VL_SERVICE_URL=http://127.0.0.1:18082 \
python backend/tools/evaluate_dataset.py \
  --dataset <数据集根目录> \
  --out <证据输出目录> \
  --split test \
  --input-kind scan
```

运行过程使用临时隔离的 SQLite 数据库与上传目录，把数据集中的 PDF/PNG 作为真实上传输入跑完完整流水线，再与金标比对。输出目录包含：

- `evaluation.json`：符合 `evaluation.schema.json` 的公开评测摘要；
- `details.json`：逐票计分明细与错例记录；
- `manifest.json`：输入文件与金标清单哈希；
- `tasks/`：每票任务的实际 CheckTask 输出快照。

## 4. 持久化发布与 API 读取

在评测命令中追加 `--publish <持久化目录>`（生产环境为 `~/app/shared/data/evaluation`），脚本会将通过校验的评测摘要写入 `runs/` 历史目录，并原子更新 `latest.json`：

- `GET /api/v1/evaluation/latest`：返回最新发布的 `Evaluation` 摘要；尚未运行评测时返回 `status: "NOT_RUN"`；若摘要文件损坏或 `counts` 与 `metrics` 验算不一致，则返回 `status: "FAILED"` 且隐藏指标数值。
- `GET /api/v1/evaluation/runs`：按时间倒序返回最近发布的最多 30 份评测批次摘要，供前端按输入通道与运行时间切换查看。

由于生产环境的 `DATA_DIR` 位于跨版本共享目录，日常代码发版与回退不会清除已发布的评测档案；每份档案均通过 `scope.code_revision` 明确标识被测代码提交版本。
