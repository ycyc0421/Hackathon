# 系统评测与持久化

评测页面展示固定数据集上的后端实测结果，不随普通上传自动跑分。部署探针通过、金标夹具中的 COMPLETED 均不是评测分数。

## 数据与范围

当前支持 synthetic-hackathon-v2 数据包：100 票、300 份文本 PDF、30 张派生 PNG、30 份派生扫描 PDF；划分按货票为 train 70、validation 15、test 15。原件、金标及来源说明由数据包提供，输入须通过 input_sha256.json 核对。整个输入及金标清单另计算 SHA-256，写入结果。

该数据集已用于开发与历史回归，即使选择 test 划分，也不能宣称盲测或未见数据泛化。扫描变体与文本原件属于同一业务票，按输入通道分批展示，不相加当作独立样本。缺少 EDI、非英文、多版式与真实业务覆盖。

规则来源快照是来源证据，不是适用性金标。来源仍标 legal_verified=false，风险提示不计分；也不把包中的 TEST_ONLY 证书引用规则当作法规真值。

## 计分

- 字段：以文件名、商品货号、字段键、归一值、单位为事实，统计多重集合的 TP/FP/FN。漏字段计 FN，额外值计 FP，错值同时计 FP/FN；同一事实重复输出也会计多读。仅评分金标定义的字段键，但不按当前后端支持列表缩减金标分母，尚未实现的地址等字段仍计漏读。
- 字符串：仅做 NFKC、大小写和连续空白归一。数值按十进制消除表示差异；不使用被测系统自己的归一逻辑，不把中英品名自动判等，不以容差掩盖金额错误。
- 商品身份：按输出的货号关联；不能唯一关联时视为未对齐，不按商品顺序或显示名猜答案。页码、坐标和单证类型不包含在当前字段分数内。
- 冲突：以商品货号和字段键标识 CONFLICT，按微平均计分；漏检、未检查和失败都不能作为正确。内部风险、缺失提示不充当 CONFLICT。
- precision=TP/(TP+FP)，recall=TP/(TP+FN)，F1=2TP/(2TP+FP+FN)。分母为零返回 null，不能补为 100%。错误分类可能重叠，不直接相加当作错误总数。

## 运行

先安装 backend/requirements.txt，在已提交且干净的工作区执行。将数据包解压到本地私有目录，原件和历史运行输出不自动提交到公共仓库。

    python backend/tools/evaluate_dataset.py --dataset <数据包根目录> --out <新证据目录> --split all --input-kind text

扫描评测在拥有模型依赖的服务器上运行，并设置 PADDLE_VL_SERVICE_URL=http://127.0.0.1:18082。input-kind 使用 png 或 scan；每次命令独立进程运行。脚本使用隔离数据库和上传目录，关闭通用 LLM 兜底，扫描通道只调用已预热的本机 VL；不会重启生产模型服务。

输出包括 evaluation.json（公开摘要）、details.json（逐票分数及错例）、manifest.json（输入与金标指纹）、tasks/（实际接口输出）。金标从不上传给后端模型。保存被测代码提交和实际输入通道，失败任务保留在分母内。超时、输入损坏等运行中断不会发布半份摘要。

## 持久化与读取

加 --publish <持久化评测目录> 可将完成摘要保存在 runs/ 下，并原子替换 latest.json。证据目录和摘要目录分开，API 不公开原始单证及逐票正文。

后端默认读取 DATA_DIR/evaluation/latest.json；生产 DATA_DIR 已链接共享任务目录，因此正常发版和回退不会删除结果。也可用 EVALUATION_RESULT_PATH 显式指定摘要文件。每次请求重新读取，发布新结果无需重启服务。

- GET /api/v1/evaluation/latest：返回最新 Evaluation；没有文件为 NOT_RUN，文件损坏或计数与分数不一致为 FAILED，不展示成功指标。缺 scope 的旧结果不判失败——分数照常展示，只是无法说明适用范围。
- GET /api/v1/evaluation/runs：返回最多最近 30 份 Evaluation 摘要，数组元素沿用 Evaluation Schema。读坏的记录显示 FAILED，不静默当作通过。前端可选择不同通道和时间的结果。

历史结果不因代码更新自动失效或变成当前版本的成绩；以 scope.code_revision 为被测版本，页面必须展示（缺 scope 的旧结果除外，页面需如实标注范围未记录）。运行分数不是模型能力承诺，不设未经讨论的达标线。
