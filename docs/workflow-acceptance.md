# 候选工作流验收与评测准备

## 可重复的接口验收

在候选代码根目录运行（建议 Linux，使用候选依赖环境）：

```bash
python backend/tools/accept_workflow.py
```

程序使用临时 SQLite 和独立上传目录，不访问生产数据库。输出到忽略提交的 `backend/.out/workflow-acceptance/`：两份可供浏览器上传的 JSON 样例、完整 JSON/HTML 报告、`acceptance.json` 检查记录。非零退出即失败。

样例初始件数均为 120 CARTONS，修正一份为 121 CARTONS 后应出现件数冲突；原任务不变，原始读数保留，修正值标记 LOW_CONFIDENCE。检查覆盖幂等重试、过期哈希拒绝、报告下载、数据库重新打开及审计保留。这是合成结构化输入验收，不是 OCR 质量或生产重启测试。

## 正式评测方案（待团队确认）

- 数据：将合成样例和真实授权单据分开；确定训练/调试与最终评测集合，避免用调过的样例宣称真实准确率。
- 金标：由 C/D 确认文档类型、票级字段、商品行、行间对应关系、冲突/缺失/无法判定标签；分歧须复核。
- 指标：文档类型准确率；字段归一值准确率与覆盖率；商品行对齐准确率；冲突检出精确率/召回率及误报；失败率、耗时和峰值内存。
- 口径：缺失、OCR 不确定、无法归一和未检查项单独统计，不能当成正确匹配；记录每个指标的分子、分母及版本。
- 规则：只评估已核实且适用条件明确的规则；未经核实提示单独展示，不计为合规判定准确率。
- 交付：保存样本清单、金标版本、代码与模型版本、逐样本结果和错例分析；方案文档不等于实现评测接口，目前仍为 NOT_RUN。
