### OLD01 金额表头把行号 1 当作有效金额

**现象：** CI 和 PI 原件总额均为 GBP 5049.60，现有提取均得到 EXTRACTED、normalized_value=1，两份错误值又被比对为 MATCH。

**原因：** 金额正则把 AMOUNT 表头当金额标签，\s* 跨过换行后匹配商品序号 1；整页搜索没有把命中限制在金额单元格或总额区。

**修复方向：** 金额必须绑定金额列或可信总额标签；数量、行号、重量不能成为金额候选。无可靠列归属时给未识别或未检查状态。

**代码：** [extract.py _m_total_amount](https://github.com/ycyc0421/Hackathon/blob/76ffb556af2c6fa0193172bcf5f71cd72d7cf912/backend/app/pipeline/extract.py#L217)。

### OLD02 净重被当成毛重且净重被误标未载明

**现象：** PL 明确写 NET 463.60 KG、GROSS 503.43 KG，现有毛重却是 463.60，净重为 NOT_IN_DOC。

**原因：** 毛重标签只支持 G.W. 或 GROSS WEIGHT/WT，不支持 GROSS KG 或 GROSS 数值；随后裸 kg 兜底取首个 kg 数值，恰好命中净重。净重匹配器同样不支持 NET KG 或 NET 数值。

**修复方向：** 按列名和总计标签识别 NET/GROSS，补充别名；禁止在有明确 NET/GROSS 语义时将裸 kg 数值猜成毛重。

**代码：** [extract.py _m_gross_weight](https://github.com/ycyc0421/Hackathon/blob/76ffb556af2c6fa0193172bcf5f71cd72d7cf912/backend/app/pipeline/extract.py#L170)。

### OLD03 二维表格被拆成独立文本行导致商品行消失

**现象：** 三份均返回 0 个商品行，最终 items=[]、0 冲突、3 个未识别条目；SKU-0002-1 的 CI/PI 880 与 PL 888 没有参与逐 SKU 比较。

**原因：** 默认 PDF 文本提取逐单元格输出换行；表头探测要求同一行命中至少三个列名，原件表头各占一行，直接跳过。列名完整匹配也不覆盖 DESCRIPTION / SKU、NET KG、GROSS KG 等复合标签。

**修复方向：** 保留坐标或版面表格结构，按单元格和行重建；用 SKU 对齐，不按行号跨文件匹配。检测到表格但无法还原时明确标记比较未完成。

**代码：** [rows.py _looks_like_header](https://github.com/ycyc0421/Hackathon/blob/76ffb556af2c6fa0193172bcf5f71cd72d7cf912/backend/app/pipeline/rows.py#L86)。

### OLD04 箱数截取包含后续重量和体积导致归一失败

**现象：** PL 已有 55 CARTONS，但 raw_value 被截为 55 CARTONS | NET 463.60 KG | GROSS 503.43 KG | 1.073 CBM，状态 NORMALIZE_FAILED。

**原因：** 件数匹配后继续截取整段尾部文本，没有在管道分隔符或下一字段标签处停止；数字归一接收到多项数值。

**修复方向：** 只归一命中的数值与包装单位，完整原文另放 raw_text；行项 22+25+8 与票级 55 分层保存，不能把行和合计重复相加。

**代码：** [extract.py _m_packages](https://github.com/ycyc0421/Hackathon/blob/76ffb556af2c6fa0193172bcf5f71cd72d7cf912/backend/app/pipeline/extract.py#L130)。

### OLD05 Document No 标签与不同单据编号语义未覆盖

**现象：** 文本层完整保留 CI-00002、PI-00002、PL-00002，发票号字段仍未识别；现有通用字段也没有独立保留这三类本单据编号。

**原因：** 编号正则只认 INVOICE NO/NUM/NUMBER 等，未覆盖 Document No。形式发票和装箱单本单据号，与关联商业发票号不是同一语义。

**修复方向：** 区分本单据编号、商业发票引用号和不同单据类型；不要把三种 Document No 都映射为 invoice_no 并要求相等。新增契约字段时与 C/D 同步。

**代码：** [extract.py _m_invoice_no](https://github.com/ycyc0421/Hackathon/blob/76ffb556af2c6fa0193172bcf5f71cd72d7cf912/backend/app/pipeline/extract.py#L303)。

### OLD06 主体与描述标签被当作字段内容

**现象：** shipper=/ EXPORTER，consignee=/ IMPORTER，description=SKU；真实公司名和逐行商品描述没有成为这些字段的有效值。

**原因：** SELLER/BUYER/DESCRIPTION 标签命中后，剩余的 / EXPORTER、/ IMPORTER、/ SKU 被视为非空内容；没有继续定位对应值区域。

**修复方向：** 完整标签匹配，并从对应单元格读取值；排除标签词和表头。主体需要保留左右列对应关系，商品描述需要保留 SKU 所在行关系。

**代码：** [extract.py _labeled_text](https://github.com/ycyc0421/Hackathon/blob/76ffb556af2c6fa0193172bcf5f71cd72d7cf912/backend/app/pipeline/extract.py#L397)。

### OLD07 OCR 表格适配器拒绝合法合并单元格与多表页面

**现象：** 不调用模型的有效 HTML colspan 探针报“合并单元格无法可靠对应字段列”；真实且正确的 PaddleOCR-VL 输出有主体表与商品表，适配器报“未识别出唯一的商品明细表”。普通 OCR 实际表头探测还返回 None。

**原因：** _TableParser 遇 colspan/rowspan>1 直接抛错；_table_lines 强制整页只能有一张表；_recognize_image 将适配异常包装成整页 OCR 失败。表头启发式对 DESCRIPTION / SKU 等标签还会绕过表格路径。

**修复方向：** 按区域和业务列选择商品表，正确展开合法合并网格；只有归属仍有歧义的字段或区域才降级。不能简单删除守卫、选择第一张表或静默丢掉其他表。

**代码：** [paddle_reader.py _table_lines](https://github.com/ycyc0421/Hackathon/blob/76ffb556af2c6fa0193172bcf5f71cd72d7cf912/backend/app/pipeline/paddle_reader.py#L56)。

## 验收清单

- 编号：保留 CI-00002、PI-00002、PL-00002 各自的单据身份与原文来源，不把三种本单据号当成应相同的字段。
- 商品：三份均识别出三个 SKU；SKU-0002-1 的数量为 880 / 880 / 888，明确报冲突并展示各文件原文；另两个 SKU 分别为 5000、4000。
- 装箱单：22、25、8 箱与整票 55 箱分层保存；整票净重 463.60 KG、毛重 503.43 KG、体积 1.073 CBM。
- 金额：CI 与 PI 都是 GBP 5049.60；序号 1 不得成为金额。PL 没有金额时保持未载明或不适用，不生成猜测金额。
- 主体和描述：返回实际公司名与商品描述，不返回 EXPORTER、IMPORTER、SKU 等标签词。
- 状态：比较失败、未识别、缺失、不适用分别表达；0 冲突不能替代“关键字段已完成比较”。
- 来源：至少保留文件、页码、原文；版面读取或 OCR 坐标需随结构保存，不能仅留下拼接后的字符串。
- 合并与多表：使用已保存的正确双表 OCR 输出，以及包含合并单元格的合法表格验证；不可靠的列归属继续拒绝或降级，不能猜列。

## 实验与复现

文本层读取、字段提取、比较均使用实际原件。结果为 0 个商品目录条目、11 条比对、0 冲突、3 条未识别，数量冲突未被检出。商业发票和形式发票的错误金额 1 被判为 MATCH，说明相同的错读值也能形成假一致。

之前已完成传统 PaddleOCR 和 PaddleOCR-VL-1.6 原精度/Q8 对照。原精度与 Q8 在这三页的 57 个选定字段检查均通过，说明识别输出可包含正确值；这不是完整数据集准确率或所有扫描件的能力证明。本轮复用保存的原始模型输出检查适配器，不重复调用模型。

```powershell
python reproduce_root_causes.py --repo <指定提交的仓库路径> --inputs inputs/SHP-00002 --ocr-output evidence/ocr-reference --out evidence/recheck
```

脚本会禁用 OCR 和外部模型调用，保存文本层、抽取结果、比对结果及适配器探针。退出码 0 表示诊断运行完成，不代表单据验收通过。以输出中的字段值、状态和商品行数量判断。
