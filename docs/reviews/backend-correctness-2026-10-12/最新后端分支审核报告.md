## NEW01 结构化 JSON 漏填行数量被误当单一来源

**优先级：P1。** 上传项目 JSON 时，装箱单某个已对齐商品行缺少必需数量，系统遗漏该缺失项，显示 SINGLE_SOURCE，不进入正常缺失处理流程。

**触发输入：** CI 和 PL 都有 SKU-A1、SKU-B2 两行。A1 两份均为 100 PCS；B2 在 CI 为 200 PCS，在 PL 省略 quantity。票级必需信息已填写，此探针仅刻意漏掉 PL 第二行数量。

**实际结果：** PL 第二行只有 item_code、description，没有 quantity 字段。因为第一行已有 quantity，票级 quantity 又被标为 NOT_IN_DOC。B2 的数量比较只包含 CI，状态 SINGLE_SOURCE；PL 漏填没有进入 values 中。

**预期结果：** PL 的 B2 quantity 为 MISSING_IN_DOC，原值为 null，B2 数量比较为 MISSING_IN_SOME，明确显示哪个文件漏填。A1 应仍为 MATCH，不受影响。

**代码位置：** [trade_json.py 行 70 至 79](https://github.com/ycyc0421/Hackathon/blob/685d6e15618cb882b5586cea1341f16527dee18d/backend/app/pipeline/trade_json.py#L70-L79) 仅要求行有货号与描述，_fields 只生成已提供字段；随后用所有行字段的并集抑制票级缺失。[compare.py 行 399 至 410](https://github.com/ycyc0421/Hackathon/blob/685d6e15618cb882b5586cea1341f16527dee18d/backend/app/pipeline/compare.py#L399-L410) 只收集已存在字段，没有补入应提供但缺失的行来源。

**修复方向：** JSON 适配器按单证类型逐行补齐字段及状态；比较层核对整个商品组的所有文件成员，不能把字段不存在直接视为不适用。字段在另一行出现不能证明当前行已提供。

**复现：**

```powershell
python reproduce_json_missing_quantity.py --repo <最新提交的仓库路径> --out evidence/recheck-json.json
```

当前输出 bug_reproduced=true、actual_status=SINGLE_SOURCE、expected_status=MISSING_IN_SOME。这是直接调用新适配器和比较引擎的组件复现，不是线上上传任务。
