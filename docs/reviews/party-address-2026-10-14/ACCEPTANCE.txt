地址提取、比较与人工修正：脱敏验收摘要

问题：公司名称已提取但地址未进入比较，文本 PDF 中同一买家不同地址的冲突漏报。新增地址字段后，还需保证人工修正与首次提取采用同一归一规则，不能把 N/A 等占位符判为一致。

实现范围
- shipper_address / consignee_address 为可选票级 STRING，原公司名称字段独立保留；未出现地址不增加必需缺失项。
- 独立地址模块识别明确标签或可靠顺序主体块，保留完整多行原文与页码；仅归一 Unicode 宽度、大小写、空白和逗号间距。
- 门牌、单元、邮编和词序差异均保持严格比较；双列归属不可靠、冲突重复块、空标签与伪值明确不可用，长地址不截取前缀当完整值。
- 人工修正复用相同地址归一；无效修正返回 422，原任务和审计不变，原文证据始终保留。
- 本 PR 基于 main 638e18c，独立于 EDI PR #70；不修改 OCR、主体匹配、比较引擎、原件、数据库 Schema 或前端源文件。

验证与来源
1. 本 PR 的 main 独立分支已重新执行完整后端：216 passed、3 既有 Windows skips、30 subtests passed。配置了外部原始数据路径，3 个原件回归实际通过；与 EDI 组合候选的测试数量不同。
2. 67 项新增地址回归：53 项自动提取/比较及原始合成 PDF 回归，14 项真实 API 修正回归。外部原始数据仅通过 HACKATHON_ADDRESS_DATASET 读取，不随 PR 发布；缺配置时明确跳过 3 个原件回归。
3. 本地“EDI + 地址”候选 7859a6c 的最终后端回归：306 passed、3 既有 Windows skips、30 subtests passed。这里是组合候选证据，不冒充本 PR 在 main 上重新执行的计数。
4. 同提取/比较实现的 15 票、45 份合成原始文本 PDF：冲突检出从 TP6/FP0/FN3 改善为 TP9/FP0/FN0，SHP-00090、00093、00100 地址冲突全部检出。完整地址保留城市/邮编，不为迎合只有街道的旧金标截断值；不声称整体字段精度或泛化准确率。
5. 固定候选的地址修正重点接口复验 90/90，通过等价地址、伪值拒绝、真实门牌差异、普通数量修正、报告/归档、幂等、重开 SQLite 和原件 SHA 检查。原 7 项失败完整保存在本地，修复后结果另存。

边界
- 前端差异/证据/报告已有通用字段展示；地址尚未加入人工修正下拉白名单，本 PR 只完成后端 API 与自动比较。
- 全球地址缩写/翻译等价、OCR双列表格地址全覆盖、正式规则适用性不在本轮验收范围。
- 用户暂缓的前端评测范围/历史呈现、刷新后原件入口未改。headless 原生 PDF 视觉渲染未确认；文件入口、页码与下载字节已验证。
- 未部署本 PR。公开内容仅源码、合成测试与本摘要；不附原件、原始接口返回、日志、数据库、模型、机器路径或凭据。
