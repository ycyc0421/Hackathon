# 项目要求

本文记录对本项目构成约束的外部要求，供实现与排期参考。

## 选题与目标

赛题方向为跨境物流单证智能转换与合规校验。要求解决的核心问题为：

同一票跨境货物涉及报关单、提单、装箱单等多份文件，格式和语言不统一，人工核对效率低；单证不一致可能导致业务异常（滞港、罚款、退运）。

### 要求具备的三项能力

1. **解析** PDF、图片、EDI 等格式单证，提取 HS 编码等关键字段。
2. **交叉比对**同票货物的多份单证，标记不一致项。
3. **依据目的国规则**，提示证书缺失或编码归类风险。

字段集合、置信度阈值、规则覆盖的国家数量、前端技术栈均未在要求中指定，由团队自行确定。

## 交付材料

| 项 | 要求 |
|---|---|
| 问题与方案说明 | 目标用户、业务痛点、使用场景、技术路线、数据来源、预期价值 |
| 成果 | 原型演示或方案文档均可；本项目按可用原型推进 |
| 验证材料 | 输入、输出、关键指标、已知限制。数据可使用公开数据、模拟数据或合规自采数据 |
| 路演展示 | 5 分钟以内的演示视频或现场演示，附必要使用说明 |

成果须能正常访问、运行或复现。

### 评分构成（共 100 分）

| 项 | 分值 |
|---|---|
| 成果完整性与可用性 | 30 |
| 问题价值 | 20 |
| AI 与技术实现 | 20 |
| 创新 | 15 |
| 落地潜力 | 10 |
| 展示表达 | 5 |

单项分值最高的是"成果完整性与可用性"。这直接影响排期取向：可运行的窄原型优于无法运行的全功能设想。

## 职责边界

本项目由多人分工推进。前端侧负责界面、接口规范、前后端对接、金标人工核验与评测看板。

本仓库中的契约文档只覆盖前端需要对接的部分：前端展示所需的数据格式，以及前端向后端提出的接口要求。单证抽取算法、数据库设计、合规规则内容不在本仓库范围内。

## 数据来源

可使用开源或公开数据集，亦允许使用模拟数据与合规自采数据。数据的具体来源与许可由数据侧确认后记录。
