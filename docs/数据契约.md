# 数据契约说明（CheckTask / Evaluation）

本文档定义前端与后端之间交换的核心数据结构与状态枚举语义。机器可读的 JSON Schema 位于 [`docs/schema/`](schema/)，仓库示例数据通过 `npm run validate` 校验，真实接口输出可通过 `node backend/tools/validate_outputs.mjs <输出目录>` 校验。

> 结构化报告导出（`view=content` / `view=archive`）的数据契约详见 [报告内容接口说明（v2）](report-content-api.md)。

---

## 一、核心设计原则

1. **证据层与比对层分离**：
   - `extractions`（第 1 层）：记录每份文件抽出了什么，保留原文片段（`raw_text`）与原始读数（`raw_value`），作为可回溯的证据。
   - `comparisons`（第 2 层）：记录同一字段（或同一商品下的同一字段）跨多份文件的比对结论。
2. **显式区分「不适用 / 未找到 / 未校验」**：
   - 单证本不具备某字段（`NOT_IN_DOC`）、应当具备却未抽到（`MISSING_IN_DOC`）、规则未覆盖或无法对齐（`NOT_CHECKED`）均使用独立枚举值，绝不省略或混同为“一致通过”。
3. **系统不裁定哪份单证正确**：
   - 比对条目的 `canonical_value` 恒为 `null`；系统仅标出差异并提供核对建议（`suggested_action`），由业务人员依据原件做出最终判断。

## 二、状态枚举定义

### 1. 任务状态（`task.status`）

| 枚举值 | 含义 |
|---|---|
| `PENDING` | 任务已创建，排队等待处理 |
| `PROCESSING` | 正在解析单证或执行比对 |
| `COMPLETED` | 全部文件处理完成（仅代表流程结束，不代表无差异） |
| `PARTIAL` | 部分完成：部分文件解析成功并产出比对，部分文件失败或不支持 |
| `FAILED` | 任务整体失败，未产出有效比对结果 |

### 2. 单文件处理状态（`document.process_status`）

| 枚举值 | 含义 |
|---|---|
| `UPLOADED` | 文件已接收，排队等待解析 |
| `PARSING` | 正在解析该文件 |
| `EXTRACTED` | 字段抽取完成 |
| `FAILED` | 文件解析失败（原因记录于 `error_message` 与 `errors[]`） |
| `UNSUPPORTED` | 文件格式暂不支持 |

> 任务处于 `PROCESSING` 期间，`documents` 按上传顺序增量更新已开始处理的文件快照，直到终态包含全部上传文件。

### 3. 单文件字段状态（`field.status` / `values[].field_status`）

| 枚举值 | 含义 |
|---|---|
| `EXTRACTED` | 正常抽出并完成归一化 |
| `LOW_CONFIDENCE` | 已抽出但置信度较低（如经受控 OCR 字符校正），需人工核对 |
| `NOT_IN_DOC` | 该类单证按规则本不承担此字段（如提单不含成交总金额） |
| `MISSING_IN_DOC` | 该类单证应当包含此字段，但在文件中未找到 |
| `UNRECOGNIZED` | 定位到字段区域但未能识别出有效值 |
| `NORMALIZE_FAILED` | 读出了原文但无法转化为可比对的标准值（如歧义日期） |

### 4. 跨文件比对状态（`comparison.status`）

| 枚举值 | 含义 | 是否列入待复核 |
|---|---|---|
| `MATCH` | 参与比对的已识别值一致 | 若任一来源为 `LOW_CONFIDENCE`，仍列入待复核 |
| `CONFLICT` | 多份文件均有值且不一致 | 是 |
| `MISSING_IN_SOME` | 部分文件有值，部分应有该字段的文件缺失 | 是 |
| `NOT_CHECKED` | 当前规则未覆盖或商品行无法可靠对齐 | 是 |
| `UNRECOGNIZED` | 相关文件均未能识别出有效值 | 是 |
| `SINGLE_SOURCE` | 仅有一份文件提供该字段，无法交叉比对 | 否（单独标注说明） |

## 三、CheckTask 数据结构

### 1. 顶层结构示意

```jsonc
{
  "task_id": "tsk_20261012_0001",
  "status": "COMPLETED",
  "created_at": "2026-10-12T14:30:00+08:00",
  "finished_at": "2026-10-12T14:30:18+08:00",
  "input": {
    "destination_country": "DE",
    "destination_country_name": "德国"
  },
  "items":       [ /* 任务内商品行目录 */ ],
  "documents":   [ /* 上传文件清单与状态 */ ],
  "extractions": [ /* 逐文件抽取结果与原文证据 */ ],
  "comparisons": [ /* 跨文件比对结论 */ ],
  "risks":       [ /* 目的国合规与归类风险提示 */ ],
  "summary": {
    "document_count": 3,
    "field_count": 19,
    "conflict_count": 1,
    "missing_count": 0,
    "risk_count": 2,
    "unrecognized_count": 0
  },
  "errors": []
}
```

### 2. 商品目录与多品名归属（`items[]`）

```json
{
  "item_id": "item_001",
  "display_name": "陶瓷马克杯",
  "description": "CERAMIC MUG 350ML WHITE",
  "line_no": 1
}
```

- `item_id` 是当前任务内的商品关联键（跨任务不互通）。
- 商品级字段（`description`、`hs_code`、`quantity`、`packages`、`gross_weight`、`net_weight`、`volume`、`total_amount`、`currency`）通过 `item_id` 关联到对应商品；整票级字段（`invoice_no`、`document_no`、`shipment_date`、`shipper`、`consignee`、`port_of_loading`、`port_of_discharge` 等）的 `item_id` 为 `null`。
- `comparisons[]` 的比较键为 `(item_id, field_key)`：商品级字段按商品分组独立比对，整票级字段跨文件比对一次。

### 3. 单文件字段抽取（`extractions[].fields[]`）

```json
{
  "field_key": "packages",
  "label": "件数",
  "raw_text": "TOTAL: SAY ONE HUNDRED AND TWENTY (120) CARTONS ONLY",
  "raw_value": "120 CARTONS",
  "normalized_value": 120,
  "unit": "CARTON",
  "confidence": null,
  "status": "EXTRACTED",
  "item_id": "item_001",
  "line_no": 1,
  "page": 1,
  "bbox": null,
  "bbox_unit": null
}
```

- 字段中文展示名统一读取后端返回的 `label`，前端不维护 `field_key → 中文名` 映射表。
- `packages`（包装件数，如 `100 CARTON`）与 `quantity`（商品数量，如 `2400 PCS`）严格区分，不自行推算。

### 4. 跨文件比对条目（`comparisons[]`）

```json
{
  "comparison_id": "cmp_1",
  "field_key": "packages",
  "item_id": "item_001",
  "label": "件数",
  "value_type": "NUMBER",
  "unit": "CARTON",
  "status": "CONFLICT",
  "canonical_value": null,
  "severity": "ERROR",
  "rule_id": "CROSS_CHECK_001",
  "note": null,
  "suggested_action": "核对发票与装箱单的件数来源，确认后更正不一致的单证",
  "values": [
    {
      "file_id": "f1",
      "file_name": "商业发票-INV20261012.pdf",
      "raw_value": "100 CARTONS",
      "normalized_value": 100,
      "field_status": "LOW_CONFIDENCE",
      "page": 1,
      "bbox": [80, 506, 260, 22]
    },
    {
      "file_id": "f2",
      "file_name": "装箱单-PL20261012.pdf",
      "raw_value": "120 CARTONS",
      "normalized_value": 120,
      "field_status": "EXTRACTED",
      "page": 1,
      "bbox": [180, 420, 240, 24]
    }
  ]
}
```

### 5. 合规与归类风险提示（`risks[]`）

```json
{
  "risk_id": "rsk_1",
  "type": "MISSING_CERTIFICATE",
  "severity": "WARNING",
  "title": "演示规则·未经核实：原产地证明核对提示",
  "detail": "仅示意风险结构；规则适用性和依据尚未核实，不构成申报要求。",
  "related_field_keys": ["hs_code"],
  "related_file_ids": [],
  "destination_country": "DE",
  "rule_id": "DE-IMP-004",
  "rule_source": "演示规则·未经核实",
  "suggested_action": null
}
```

- `type` 取值：`MISSING_CERTIFICATE` / `HS_CLASSIFICATION` / `RULE_UNCOVERED` / `OTHER`。
- `rule_id` 非空时归入「依据规则的提示」；`rule_id` 为 `null` 时归入「未经规则校验的提示」。

## 四、单证类型 × 字段适用规则表

用于区分 `MISSING_IN_DOC`（应有而未找到）与 `NOT_IN_DOC`（本单证不适用）的基准规则：

| `field_key` | 字段名 | `value_type` | 标准单位 | 商业发票 | 装箱单 | 提单 |
|---|---|---|---|---|---|---|
| `description` | 货物描述 | `STRING` | — | 必需 | 必需 | 必需 |
| `packages` | 件数 | `NUMBER` | `CARTON` | 可选 | 必需 | 必需 |
| `quantity` | 数量 | `NUMBER` | `PCS` | 必需 | 必需 | 可选 |
| `gross_weight` | 毛重 | `NUMBER` | `KGS` | 可选 | 必需 | 必需 |
| `net_weight` | 净重 | `NUMBER` | `KGS` | 可选 | 可选 | 可选 |
| `volume` | 体积 | `NUMBER` | `CBM` | 可选 | 可选 | 可选 |
| `hs_code` | HS 编码 | `CODE` | — | 可选 | 可选 | 不适用 |
| `total_amount` | 总金额 | `MONEY` | — | 必需 | 不适用 | 不适用 |
| `currency` | 币种 | `CODE` | — | 必需 | 不适用 | 不适用 |
| `invoice_no` | 发票号 | `STRING` | — | 必需 | 可选 | 不适用 |
| `shipment_date` | 装运日期 | `DATE` | — | 可选 | 可选 | 可选 |

此外，各文件自身的单据编号保存在可选抽取字段 `document_no` 中，用于在报告页文件清单展示，不参与跨单证相等比对。

## 五、Evaluation 数据结构

`GET /api/v1/evaluation/latest` 与 `GET /api/v1/evaluation/runs` 返回固定数据集上的离线评测摘要（Schema 见 [`schema/evaluation.schema.json`](schema/evaluation.schema.json)）：

- `status`：`NOT_RUN` / `RUNNING` / `DONE` / `FAILED`。
- `sample_count` 为货票数，`scope.document_count` 为参与评测的文件总数。
- `metrics` 包含 `field_extraction` 与 `conflict_detection` 的 `precision`、`recall`、`f1`（0–1 浮点数，分母为零时为 `null`）。
- `scope` 记录 `dataset_kind`、`input_kind`、`split`、`code_revision`、`scorer_version`、`dataset_sha256`、`limitations`、`metric_definitions` 及各指标的 `counts`（`tp` / `fp` / `fn`）。
