# 复杂版式与多商品表格解析修正说明（Review #38）

本文档记录针对复杂单证版式（多表共存、括号币种合计、合并单元格、单据自身编号与商业发票号区分等）的解析与比对修正规则。配套回归样本位于 [`backend/samples/review38/`](../backend/samples/review38/)，自动化测试脚本为 `backend/tools/test_review38.py`。

---

## 核心解析与比对规则

1. **金额与币种提取边界**：
   - 金额标签不跨行误取相邻文本；支持带括号币种的表头或合计行（如 `TOTAL (GBP) 5,049.60`）。
   - 装箱单（Packing List）若仅出现币种字样而无单价或金额列，保持金额为 `NOT_IN_DOC`（不适用），绝不将商品数量误拼为金额。
2. **毛重、净重与包装件数分层**：
   - 准确识别 `NET` / `GROSS` 简写及管道符分隔字段；毛重缺失时绝不拿净重数值兜底冒充。
   - 商品行级箱数（如各行 `22 / 25 / 8` 箱）与整票汇总箱数（`55` 箱）按 `item_id` 严格分层保存，不混同或重复累加。
3. **多表共存与合并单元格还原**：
   - 当页面同时存在买卖方信息表与商品明细表时，按商品表头特征唯一定位商品表；若存在多个疑似商品表或数据行跨格归属不清，则显式降级报错，不盲目跳过或猜测。
   - 对具备明确列名、连续序号与 SKU 的商品表，逐单元格还原文本并检出跨单证数量差异（如 `880 / 880 / 888 PCS` 准确判定为 `CONFLICT`）。
4. **单据自身编号（`document_no`）与发票号（`invoice_no`）分离**：
   - 新增可选整票字段 `document_no` 记录各份单证自身的编号（如形式发票号 `PI-...`、装箱单号 `PL-...`），仅用于报告页文件清单展示，不参与跨单证相等比对。
   - 仅商业发票（Commercial Invoice）的自身编号或各单证中明确标注为发票引用的编号作为 `invoice_no` 参与跨单证核对。
5. **结构化输入缺失防御**：
   - 结构化 JSON 单证输入按单证类型校验必需字段；某商品行缺失数量时准确标记为 `MISSING_IN_DOC`，跨文件比对输出 `MISSING_IN_SOME`，不会因单侧缺失而退化为 `SINGLE_SOURCE`。
