# 前端设计系统

## 原则

1. **信息优先** — 界面服务于数据，减少装饰
2. **状态可区分** — 颜色+图标+文字组合，不只靠颜色
3. **操作可确认** — 动画只用于反馈，确认交互生效
4. **不伪造数据** — 缺失的可信度、未运行的评测一律留空
5. **一层壳，不套娃** — 同一块内容只包一层盒子。层级由表面亮度差、圆角梯度
   与投影表达，不靠"卡套卡"。首页更是从简：Hero 与各区块不套卡片外壳。

## 主题（浅色 / 暗色）

主题以 `<html data-theme="light|dark">` 切换，色值全部在 `design-tokens.css`
里成对定义。**不是把浅色反相**——暗色下三件事必须显式重定：

1. **投影**：近黑底上看不见黑投影，层次改由边框承担，投影只留一点落定感。
2. **文字对比**：浅色的 `--text-muted`（gray-600）在暗底上会直接沉进背景，
   必须提到 gray-300 一档。
3. **语义色**：浅底上是"深色文字 + 浅色底"，暗色下要反过来——
   主色提亮、底色改为低透明度叠加。

解析顺序：`localStorage`（用户显式选过）→ 系统 `prefers-color-scheme`。
**用户一旦手动切过就停止跟随系统**（显式选择优先）。系统偏好变化会实时跟随。
打印使用浅色纸面与深色文字，不沿用暗色屏幕配色。
防闪烁靠 `index.html` 里的同步内联脚本（在样式表之前执行），
`state/theme.js` 的 `initTheme()` 是兜底。`color-scheme` 一并设置，
让滚动条与原生控件跟随主题。

### 暗色主题的强调色

暗色下**强调色就是主操作色**：主按钮 = 柠檬黄绿实底 + 近黑文字，
链接与选中态同色。蓝色退居"信息/中性强调"，不再出现在主按钮上。

强调色取自 velopay 的荧光绿（色相 120°、亮度 ~90%、彩度 ~0.19）。
**浅色主题下同一色相必须压亮度、降彩度**（500–700 档才可用）：
velopay 那档亮度在近黑底上是"电光"，放到近白底上就是一片荧光黄。

暗色背景转**中性近黑**（彩度 0.002–0.004），不再偏蓝：偏蓝的暗底会让
柠檬绿显脏，也会读成"变暗的蓝色应用"。浅色主题仍保留冷灰（250）。

环境光也分主题：暗色下主光转**中性白**（velopay 的高级感来自白色柔光，
不是彩色光），右下补光保留一点强调色；浅色下两团光都保持冷调。

### 对比度

普通文本目标 WCAG AA（4.5:1），大字 3:1。已实测两套主题共 40+ 处组合，
最低 4.82:1（浅色下选中页签）。**徽章与提示条的文字一律用 `-strong` 档**：
语义色的基色是给大色块和描边定的，直接当 12px 小字用不够对比
（修复前浅色下橙 3.06:1、绿 4.36:1）。

## 视觉语言：纸感工作台

产品的内核是**单证与比对**，界面据此按「桌面 → 纸 → 下沉」三层表面组织：

| 层 | Token | 用途 |
|---|---|---|
| 桌面 | `--surface-desk` | 页面底。带细点阵纹理与两团光晕，是"纸"的衬托 |
| 纸 | `--surface-raised` | 内容卡。白底 + 极轻投影，浮在桌面上 |
| 下沉 | `--surface-sunken` | 卡内子块。把一组信息从卡片正文里分出来 |

边框（`--border`）已减淡，**只作最后一道保底，不承担主要层次职责**。
`--border-strong` 用于需要明确边界处（拖拽区、表头、流程穿线）。

**首页与功能页的纪律不同**：首页是入口页，允许品牌表达（Hero 装饰、光晕、
滚动揭示、一次性的流程穿线动画）；功能页保持克制，动效只做交互反馈。

设计变量以 `src/design-tokens.css` 为准，组件实现与全局样式见 `src/styles.css`。以下既包含当前约定，也包含新增交互应满足的设计要求；不等于已完成无障碍认证。

```css
--gray-100: oklch(96% 0.004 250);  /* 悬停 */
--gray-200: oklch(90% 0.006 250);  /* 边框 */

--gray-600: oklch(45% 0.012 250);  /* 次要文本 */
--gray-900: oklch(18% 0.006 250);  /* 正文 */

/* 主色（沉稳蓝）——操作、选中、链接 */
--blue-500: oklch(52% 0.14 240);
--blue-600: oklch(45% 0.14 240);   /* hover */
--blue-700: oklch(38% 0.13 240);   /* active */

/* 品牌第二色（青绿）——只做数据与品牌点缀：图表、指标条、首页装饰。
   与蓝同属冷调（色相 240 → 195），不抢语义色辨识度：
   成功/警告/错误三色必须始终比它更"响" */

--success: oklch(56% 0.15 148);    /* 参与比对的值一致，不代表整票合规 */
--warning: oklch(66% 0.16 62);     /* 待复核/不一致 */

--info: oklch(60% 0.12 230);       /* 提示 */
/* 语义色的"深档"，用于浅底上的文字（--danger-strong 等），保证对比度 */

--surface-desk: oklch(96.6% 0.005 250);
--surface-raised: #fff;
--surface-sunken: oklch(97.2% 0.004 250);
```

### 动画

```css
--duration-fast: 120ms;      /* 状态切换 */
--duration-base: 200ms;      /* 元素进入/尺寸补间 */
--duration-slower: 1600ms;   /* 长反馈：高亮淡出、阶段点脉冲 */
--duration-page: 620ms;      /* 页面层叠切换专用：整张纸飞过一屏 */
--ease: cubic-bezier(0.4, 0, 0.2, 1);
--ease-page: cubic-bezier(0.32, 0.72, 0, 1); /* 页面层叠与首页示意图专用 */
```

动画分两层，纪律不同：

- **功能反馈动画**（绝大多数）：只做确认交互生效的反馈，缓动唯一 `var(--ease)`，
  时长在 fast/base 档。**只做**：按钮反馈、状态切换淡入、筛选 chips 切换、
  表格与对照的视图切换、上传进度、表格 hover、文件拖放高亮。
  **不做**：数字滚动、装饰性动画。
- **入口级动画**（少数、有引导目的）：页面层叠切换（`--duration-page` /
  `--ease-page`）、首页单证示意图的一次性散开、上传完成后的「查看比对结果」
  描边引导（`--duration-slower`）、原文预览抽屉的右侧滑入（与页面层叠同一套
  纸张语言，见「原文预览抽屉」一节）。
  允许有表现力，但**只播一次、不循环**，播完界面回归克制基线；
  reduced-motion 下整体降级（层叠切换瞬切、描边完全不出现）。

补充原则：

- **连续输入不过渡，离散切换必过渡**：resize、拖拽这类连续输入驱动的
  布局变化不做任何过渡——每帧过渡会产生追鼠拖尾，比不动更坏；离散
  状态切换（筛选、视图互换、增删条目、切页）必须过渡。这就是
  「为什么窗口 resize 没有动画」的设计答案。
- **时序纪律**：所有 transition/animation 必须显式使用 `var(--ease)`，
  禁止缺省（linear / 浏览器默认 ease），也不另用 ease-in/ease-out 变体；
  尺寸类过渡（width / height / grid-template-rows）统一 `var(--duration-base)`，
  避免尺寸变化与颜色变化节奏不一致。
- **平级视图的互换**：同一信息的两种排布互为切换（如差异页的表格 ↔ 对照）时，
  新内容快速淡入 + 容器高度平滑过渡（距离自适应，见下条）；切换两端的视觉重量
  应相当，不出现「切过去反而更空」的方向感。
- 列表内容随筛选整体切换时，整块淡出淡入，不做逐条 stagger。
- **高度必须过渡，但距离自适应**：容器内增删内容导致高度变化时，一律走公共工具
  `utils/animateHeight.js`，禁止只 fade 不管高度——旧内容移除瞬间容器
  高度坍缩，周围内容会跳位。高度差超过阈值（`HEIGHT_TWEEN_MAX_DELTA`，300px）
  时补间拉扯感强，改用 `animateHeightAdaptive` 分流：差值内维持高度补间
  （时长封顶 `--duration-base`，不随距离变长）；超限不做高度动画——旧内容
  `--duration-fast` 淡出，新内容带轻微 translateY（4px）淡入，容器直接到位；
  页面因此变短导致 scrollY 悬空时，平滑滚动补偿到锚点卡片顶部对齐页头下沿。
  筛选切换与卡片内视图互换同一策略。
- **页面切换是纸张层叠，不是 out-in 淡入淡出**：Transition 无 `mode`，
  新旧页并行渲染、同时在 DOM。方向感按路由 `meta.order` 比较得出：
  前进（去向 order 更大）新页从右侧飞入，后退镜像（左入）；旧页在
  `before-leave` 里量好视口位置后 `fixed` 脱流锁定视觉原位
  （top 是视口坐标，天然补偿了 `-scrollY`，新页滚动不会带它走），
  在原地缩小/滑出。时长 `--duration-page`、缓动 `--ease-page`，
  reduced-motion 下降级为瞬切。
- **纸张必须有纸面，但不加暗层**：切页过渡的载体是版心内容列 `.page-inner`，
  它**只负责限宽与居中，本身不是一张可见的卡片**（不加白底/圆角/边框/投影）——
  否则会和外层 `.card` 叠成"卡套卡"。层次由各元素自己的投影与缩放表达。
  裁切边界是视口（`body { overflow-x: clip }`），不是版心。
  **不在层叠期间压暗桌面**：曾在 `.content.stacking` 上加过一层全屏遮罩让纸张
  边缘更清楚，但遮罩相对 `.content` 定位，滚动到页面下半段时只盖住首屏高度，
  表现为"底部莫名变暗一块"，比纸张边界读不出来更糟。前进时新纸从 `translateX(100%)`
  整张飞入、左缘带静态投影；旧纸 `scale(0.9)`、圆角显出、纸面遮罩压暗到 0.18。
  后退镜像：上层纸向右抽走，底下的纸从 0.9 回弹。层叠期间 `.content.stacking`
  显出 `--gray-300` 的「桌面」，纸张边界才读得出来。缩放原点由 JS 对准视口
  中心（长页面的纸张中心可能远在视口外）。只动 transform / opacity，压暗用
  遮罩层而不是逐帧重绘的 `filter`。窄屏缩放收敛到 0.94。
- **滚动恢复在 enter 钩子同步完成**：并行过渡下，`enter` 触发时新页已插入、
  旧页已 `fixed` 脱流不撑高，文档高度即新页内容高度，`scrollTo` 不被钳位，
  且赶得上进场第一帧——禁止 `after-enter` 才滚（先淡入再硬跳，肉眼可见），
  也不能放 `before-enter`（新页尚未插入、旧页已脱流，文档只剩顶栏+页脚，
  maxScroll≈0，scrollTo 会被立即钳到 0）。滚动记忆是通用的
  每页记忆：任何页面离开都记录 scrollY，返回时该页有记录即恢复
  （不限来源页），锚点跳转优先，无记录归零。
- **切页后焦点迁移到新页标题**：页内按钮触发跳页后旧页卸载，焦点回落
  `<body>`，键盘/读屏用户位置丢失。`enter` 钩子里把焦点移到新页第一个
  `h1/h2`（`tabindex=-1` 只收程序焦点，`preventScroll` 不与滚动恢复打架）；
  首次挂载不迁移（浏览器原生行为优先）。
- **列表增删**：条目增删一律 `TransitionGroup` + 稳定 key（业务唯一值，
  禁止用数组下标——删中间项会让后续条目全部重键、补位动画失效）。
  进入/离开走 JS 精确高度钩子（`heightListItemHooks`，`:css="false"`）：
  条目留在文档流内，量真实高度后 height/padding/border/opacity 同步收放，
  文字被自己的栏位裁掉、栏位与文字一体，兄弟行随高度变化自然移动。
  禁止 absolute 脱流方案——实测栏位不收缩、文字与栏位脱离、下方内容
  突兀上移（上传页文件列表踩过的坑）。
- **高度测量必须放在 onEnter，不是 onBeforeEnter**：Vue 的 `onBeforeEnter`
  在元素【插入 DOM 之前】调用，游离节点没有布局，`offsetHeight` 恒为 0。
  在 beforeEnter 量高会让高度补间起点=终点=0：高度从不过渡，条目只靠
  padding 长出一半，等别的属性 transitionend 后内联样式被清掉瞬间弹到
  全高——表现为「出现→卡一下→弹到位」。正确姿势：beforeEnter 只做视觉
  归零防首帧闪现；onEnter 里先还原量自然高，再收起、强制 reflow、展开，
  量与还原同帧同步完成不上屏。单元素 v-if 的收合（`collapseHooks`）同理。
- **主线程重活避让动画**：文件预检测这类读文件+扫描的计算，在添加条目
  动画同帧跑会卡住补间（transition 走主线程）。预检测限读文件前缀
  （`pdfTextLayer.js` 的 `MAX_SCAN_BYTES`），并用 `requestIdleCallback`
  调度到动画之后；大段字节查找一律字节级比较，禁止循环拼字符串。

**揭示动画必须"默认可见"**：滚动揭示这类动效，隐藏样式只能由 JS 在挂载时
给"确实在视口下方"的元素加上，绝不能反过来——默认隐藏、等 JS 揭示。后者
一旦观察器漏触发（快速跳转滚动、打印、脚本未执行），内容就永久隐形了。
**动画是增强，不能成为内容可见的前提。**

**装饰性动效不依赖"刚好赶上"**：任何循环显隐的装饰元素，都要考虑它在
静态截图、视频抽帧、打印时会是什么样子。首页的扫描线（循环扫过示意图）
因此被移除，改为常驻高亮。

尊重 `prefers-reduced-motion`：JS 驱动的动画（平滑滚动、容器高度过渡）
需各自判断该偏好并降级。

## 组件

### 按钮

实现集中在 `styles.css` 按钮区，类名均为 `.btn` 复合类（不是连字符类名）：

- `.btn`：基类，即次按钮——白底灰边，36px 高，`--text-sm` 字号
- `.btn.primary`：主按钮——实色填充（`--color-primary`），一页一个主操作
- `.btn.small`：小按钮——28px 高，`--text-xs` 字号，用于卡片内联操作（如重试）
- `.link-btn`：文字按钮——无边框无背景、主色带下划线，用于低强调操作
  （如「在差异页查看」「移除」）
- `.chip`：筛选胶囊——视图/筛选项切换，非操作按钮

**字重统一 600**（`--weight-semibold`）：全站强调元素（标题、选中态）都是 600，
按钮是最主要的操作，不例外。

通用状态（`.btn` / `.link-btn` 一致）：

- hover：背景或颜色加深（`.btn` 白底变 `--gray-50`，`.link-btn` 主色变深）
- active：`.btn` 再深 + `scale(0.98)`；`.link-btn` 颜色到 active 档
- focus-visible：`outline: 2px solid var(--color-primary)`，offset 2px；
  `.link-btn` 额外带 `--radius-sm` 圆角，避免外圈切角
- disabled：`opacity: 0.5` + `cursor: not-allowed`

**已登记的变体**：`.compare-foot .link-btn`（对照面板脚注，`--text-xs`、
无下划线）。这是唯一允许局部覆盖 `.link-btn` 的场景，其它场景需要新外观时
先改基类或登记新变体，不就地覆盖。

### 表格

- 斑马纹：奇数行 `var(--gray-50)`
- hover：`var(--gray-100)`，120ms 过渡
- 表头：字重 600，sticky，`background: white`
- 数字右对齐（等宽），文本左对齐
- 数字列的**表头与数据对齐方式一致**：表头与数据用同一个 `.num` 类，
  对齐规则同源，不允许头左数右的错位
- 横向边框 `var(--gray-200)`，无竖向边框

### 下拉选择（AppSelect）

自定义下拉：触发按钮 + 浮层 listbox，焦点始终在按钮上，
`aria-activedescendant` 指路。块级模式（`block`）外观对齐 `.input`，用于表单；
`disabled` 时触发按钮不可聚焦、不展开（提交中的表单字段用），
禁用态样式与 `.input:disabled` 同一套（压暗 + `not-allowed`）。

**使用注意**：勿把组件包在原生 `<label>` 内——点选 `<li>` 会触发 label 的
激活行为，浏览器对触发按钮合成一次 click，刚收起的浮层会被重新展开。
该合成 click 是 label 的默认行为（按祖先链确定，不走冒泡分发），组件内
选项与浮层的 click 已做 `.prevent.stop`（仅 `.stop` 拦不住），正常调用
不受影响；新增调用点时仍应避免 label 包裹（label 的激活行为对自定义
组件没有语义价值）。

### 文件列表（上传页）

已选文件清单用 `TransitionGroup` 渲染，`key` 取稳定业务值
（`fileKey = 文件名:大小`），禁止数组下标。条目进入/离开为
高度收起 + 淡出（`--duration-fast`），其余条目 move 平滑补位
（`--duration-base`）。

**容器纪律**（适用于一切 TransitionGroup 列表）：

- 容器常驻挂载，**不用 `v-if` 包容器**：`v-if` 在删到最后一项时会把容器
  直接移除，条目离场钩子不执行，只剩窗口硬 resize。空态改用类绑定
  （`.file-list--empty`）把容器自身的边框/margin 一并过渡，首尾项的
  增删与中间项同样连贯。
- **持久状态列表禁用 `appear`**：`appear` 的语义是"每次挂载都播进入动画"。
  文件列表这类状态提升在 App 层、切页后还在的列表，加 `appear` 会导致
  每次切回页面都重播。条目插入本身就会触发进入钩子，不需要 `appear`。

### 状态徽章

文案与 tone 以 `src/api/labels.js` 为准，不能另造 CONSISTENT 或 MISSING 枚举。

| 状态 | 展示语义 |
|---|---|
| MATCH | 一致，绿色；含低可信值时仍需复核 |
| CONFLICT | 不一致，红色 |
| MISSING_IN_SOME | 部分缺失，警告 |
| NOT_CHECKED | 未校验，警告 |
| UNRECOGNIZED | 无法比对，警告 |
| SINGLE_SOURCE | 仅一份文件，中性 |
| LOW_CONFIDENCE（字段） | 请核对，警告 |

### 加载与空状态

- **加载**：骨架屏匹配实际布局，渐现 200ms
- **空状态**：纯文字排版（标题 + 说明），**不用 emoji 插图**——企业工具，保持克制；
  必须有说明文字（"尚未评测""没有风险提示"）
- **通过态收敛**：全通过的正向确认（"没有需要处理的条目""没有风险提示"）
  用一条细窄绿色 NoticeBar 一句话带过，**不用居中大空状态**
- **错误**：说明什么失败 + 重试按钮

### 文件 chips（报告页）

文件名清单压缩为 chips，一行多份，状态靠色点快分。

- 结构：状态色点（8px 圆，`processStatus` 的 tone → 语义色）+ 文件名 + 类型
- 失败文件：`error_message` 放 chip 第二行（`--danger` 小号字），压缩布局也不丢错误信息
- 布局：`flex-wrap` + `gap: var(--space-2)`，边框 `var(--border)`，圆角 `var(--radius-md)`

### 并排对照面板（差异页 ComparePane）

比对卡片的左右对照视图，回答「几份文件摆在一起，差异在哪」。

**为什么是视图切换而不是就地展开**：四行表格与并排对照是同一信息的**两种排布、互为平级**，
不是概要/详情的展开关系。此前用 ▶ 展开语义时，展开后的三列浅面板反而比收起态的
四行表格更矮——「展开却看到更少」违反直觉。因此触发方式改为分段控件切换。

- 触发：卡片头部**最左**的分段控件「表格 | 对照」（`.view-switch`），默认「表格」；
  视线顺序为 切换方式 → 字段 → 徽章。
  `role="group"` + `aria-label="查看方式"`，各按钮用 `aria-pressed` 表达当前选中，
  不使用 `aria-expanded`/chevron 展开语义
- 切换动画：离场内容立即隐藏（**不做离场动画、不用 absolute 定位**——crossfade
  曾使父容器高度中途坍缩、整列抖动），新内容快速淡入（`--duration-fast`）；
  容器高度只由 JS 从旧高度平滑过渡到新高度（`--duration-base`）。
  测量目标高度时须先还原最终态再量（`overflow:hidden` 使容器成为 BFC，
  子元素 margin 不再折叠，直接量会虚高一个 margin）。
  `prefers-reduced-motion` 下全局压为瞬时
- 状态模型：每张卡片记录当前视图（`table | compare`），非 Set 展开态；不持久化，
  切页重挂载后回到表格视图
- 布局：`grid` + `repeat(auto-fit, minmax(220px, 1fr))`，多文件自动换行平铺
- 每列：文件名（muted 小字）→ 值（等宽 600）+ 页码 → 原文 → 字段状态徽章 + 「查看原文」链接
- 差异强调：仅「CONFLICT 且本列归一值与其他列不同」的那一列，左边框 3px `--danger` + `--danger-bg`；一致列保持中性
- 降级：无 File 对象（mock）不渲染「查看原文」；`page` 为 null 不显示页码；值为 null 显示「—」
- 「查看原文」点击后由**原文预览抽屉**（见下节）在页面右侧就地呈现原件；
  PDF 与 EDI 不再是两套动作（新窗口 / 就地展开），统一为一个入口

### 原文预览抽屉（SourcePreview）

「查看原文」不再新开标签页——新标签页会把用户从「值 ↔ 原文」的核对动作里带走，
回来还要重新找滚动位置。改为在页面主体**右侧起一张纸**，核对在同一屏内完成。

- **实例归属**：全站（当前为差异页）只渲染一个抽屉实例，状态由所在页面持有；
  比对卡片通过 provide 的入口函数驱动它，任何一张卡片点开的都是同一张纸。
  一次只看一份原件：`{ file, page }`，页码跟着文件换，不沿用上一份的
- **切入方式复用切页的纸张语言**（入口级动画）：从右侧整张滑入，
  `--duration-page` / `--ease-page`，与页面层叠切换同源——同一套动作，
  不是新发明的一种。与切页一致**不加遮罩压暗桌面**，层次由纸自身的投影
  与左缘边界表达。`prefers-reduced-motion` 下随全局规则压为瞬切
- **定位**：`Teleport` 到 `body` + `fixed`。切页过渡会给 `.page-inner` 加
  transform，transform 祖先会成为 fixed 的包含块，抽屉若留在页内会被锁进
  纸张里、无法贴住视口右侧
- 按类型分流（`utils/sourceFile.js` 的 `sourceKind`，**只认扩展名**——浏览器对
  本地文件的 MIME 常为空或不可靠）：PDF 交给 iframe 的浏览器内置阅读器，
  预览副本声明 PDF MIME、页码拼 `#page` 锚跳页；图片按原比例显示并可滚动；
  EDI/JSON 等纯文本严格 UTF-8 解码后
  按 `pre` 原样呈现（文本插值天然转义 HTML 形似内容，禁 v-html）；
  不认识的格式不猜内容，只给下载
- objectURL 生命周期由抽屉自管：切文件先回收旧 URL，关闭即回收；
  文本读取带序号防错乱——快速连续切换时晚到的旧结果作废
- 键盘：打开时立即聚焦关闭按钮，不等待文本读取；旧读取结束不抢焦点。
  关闭时焦点还给触发按钮；页面内 Esc 关闭。PDF 阅读器有独立的按键上下文，
  焦点在其中时使用抽屉关闭按钮
- 降级与 ComparePane 同口径：无 File 对象（mock）入口不渲染；`page` 为 null
  不显示页码也不拼锚；文本解码失败如实提示，不静默替换字符；
  打印时抽屉隐藏（打印走报告页）

### 评测页指标卡

每个指标（字段抽取 / 冲突检出 / 风险提示）一张小卡，卡内三项
（精确率 / 召回率 / F1）各一条比例条 + 数值。

- **条形只表达 0–100% 的比例，不画"达标线"**：本页不设阈值，画一条线
  就会被读成及格线（AGENTS.md：不替团队设定验收阈值）
- 三项用同一主色的三档明度（`--color-primary` / `--teal-500` / `--blue-700`），
  **不用三个语义色**——它们是同一指标的不同侧面，不是"好/中/差"
- **错误分类**用横向条形，按最大计数归一，让各条之间的相对量级可读；
  条用警告色而非错误色（这是"错误分类统计"，不是"当前有错误"）
- 缺值显示 `—`，条形宽度为 0，不填任何默认数字

**计数与比例同源、同卡并置**（`.metric-counts`）：`precision`、`recall`、`F1`
就是 tp/fp/fn 的换算，分开摆会被读成两组无关数据。计数条用「下沉」表面表达
从属关系，不再加一层边框。该指标没有计数时整条不渲染，**不补 0、不显示 0/0**。

**分数的适用边界与分数同等重要**。评测页展示的是固定数据集上的实测结果，
不写清范围就会被当成泛化能力：

- **范围提示条**：输入通道 + 数据来源。`scope` 是契约里的可选字段（旧结果没有），
  缺失时如实标注「范围未记录」，**不补默认值**——省略这一段会被读成"没有范围限制"
- **已知局限**（`.limit-list`）：`limitations` 在契约里就是成句中文，不是语义代码，
  逐条直出。**不建立代码→文案映射**：那套映射会静默丢掉后端新增的条目
- **指标口径与复现证据**（`.eval-provenance`）：收进默认收起的原生
  `details/summary`（与 DocumentNumbers 的「原始读数与原文」同一做法）。
  `metric_definitions` 可能很长，`dataset_sha256` 是 64 位十六进制，
  都不适合摆在正文里；两者都是"这份分数怎么来的"，收在同一处，正文只留结论
- 某指标只给计数不给分数时（当前跑分不计风险提示）明说「本批次未评测」，
  不能让读者把"没评"读成"没问题"

**示例数据须与真实产出同形**：`web/src/mock/evaluation-done.json` 与
`evaluation-scan.json` 由 `tests/eval-mock-schema.test.mjs` 固定——符合 schema、
`counts` 能算出 `metrics`、错误分类与计数同源、局限说明保留"数据集已用于开发"。
两份夹具覆盖不同输入通道与时间，否则批次选择器没有可选项。

### 报告页结论条与统计卡

**结论条**（`.report-conclusion`）：检查概要的开头结论是全页最重要的一句话，
先于统计数字出现，必须一眼可见。

- 承载：3px 左边带 + 底色的小卡，字号 `--text-base`、字重 500
- **颜色跟随语气（tone）**，tone 与文案同源推导（`utils/reportConclusion.js`），
  不出现"坏消息配蓝底"的错位：有问题条目 `--danger` 红；含未校验或 PARTIAL
  `--warning` 橙；COMPLETED 且比对条目全部一致 `--success` 绿；其余中性灰
- summary 缺失时整段不渲染，不替后端下结论

**统计卡**（`.stat-row` / `.stat`）：每个统计数字一张小卡
（边框 + `--radius-md`），核心是「需要处理」的数字要分层：

- 零值（没有问题）：数字收敛为 `--text-muted`，无底色，不抢「没问题」的语义
- 非零：底色 + 边框 + 数字同语义色（不一致 `--danger`，部分缺失/无法比对 `--warning`）
- 中性计数（文件、抽取字段、风险提示）：保持默认卡片样式

**问题条目**（`.issue-item`）：头部（字段名 + 商品归属 pill + 徽章）→
取值区（`--gray-50` 浅底块，值用等宽 600）→ 脚注链接，三层间距
`--space-2` 节奏统一；商品归属 pill 弱化处理，查不到目录时不显示、不猜。

### 任务进度卡（上传页）

- 从上传到终态保持同一任务卡与文件列表，按真实状态就地更新，避免整块淡出重建。状态行、已处理计数和结果操作使用已有收合钩子入场。
- 后端尚未发布的文件用本地文件名占位为排队中；已发布的严格使用 process_status。排队 spinner 为灰色，上传/解析 spinner 为主色；遵循 reduced-motion。
- “已处理 x / n”中的 x 计入成功、失败、不支持三类文件终态，n 使用本地总份数与已返回份数的较大者。不得把 x 解读为成功数。
- 上传百分比只表示字节传输；100% 后仍可能等待创建任务。阶段条基于已有状态推断，不能宣称真实算法进度或预计剩余时间。

### 上传完成引导（描边动画）

任务到终态后，「查看比对结果」主按钮播一次性 SVG 描边引导：与按钮同尺寸的
rect `dashoffset 100→0` 描一圈，描边 transitionend 后再给按钮一次轻微脉冲
（一次即停）。属入口级动画：**全程只播一次**，引导用户发现出口，不循环。

- **触发条件是任务成功到终态**（COMPLETED / PARTIAL），与有没有待复核项无关：
  引导的是「结果出来了、可以去看」这个出口。处理中与失败不播——按钮那时
  还是灰色禁用态，描边没有指向。
- **触发时机**在 `collapseHooks` 展开结束之后——按钮还在「长高」的过程中
  播描边会一半被 overflow 裁掉，必须等容器展开完成。
- reduced-motion 下全局压零 transition 使描边动画不播放、描边始终不可见，
  优雅降级，不需要额外分支。

### 首页

首页是入口页，允许品牌表达；功能页保持克制。**首页不套卡片外壳**——
Hero 与各区块靠留白、分隔线与插图组织，包边会让它看起来像一堆功能卡。

**首屏与折叠线**：`.home-top`（Hero + 操作流程条）撑满顶栏以下的可视高度
（`min-height: calc(100vh - 60px - var(--space-6))`），内容纵向居中。
因此 `.home-below`（演示视频、能力说明、比对预览、演示场景）恒从折叠线
以下开始，**不滚动绝对看不到**。这比给 Hero 一个估算高度可靠：内容多高
只是把块撑得更高，不会漏出来。

- **两栏 Hero**：左侧标签 + 大标题（`clamp(34px, 4.2vw, 46px)`）+ 一句说明 +
  主/次操作 + 支持的单证类型。标题里的关键词用问题色着色（`<em>`），
  一句话自己指出重点。右侧三张单证叠放的装饰示意（`aria-hidden`，
  件数在发票上不一致、常驻高亮，旗标常驻右下），加载时散开一次。≤860px 收一列
- **操作流程条**：紧接 Hero，回答"这东西怎么用"。**不套卡片**——这里要的是
  "一条流程"，加盒子就变成"三件独立的东西"。动画是入口级的：虚线连接线
  从左端画入（`scaleX` 0→1），画完三个图标依次浮现（`--step-i` 错开），
  文字比图标再晚一档。编号用等宽字体 + 青绿
- **当前任务摘要条**：有任务才渲染（徽章 + 任务号 + 待复核数 + 「继续查看」，
  去向按有待复核进差异页、否则报告页），给用户一个「回到哪」的入口
- **演示视频入口**：使用运行时相对地址引用独立交付的视频资源，加载失败时整块隐藏；
  设置 VITE_HOME_DEMO=0 可在构建时关闭入口。演示必须说明使用合成样例、
  处理过程经过模拟，不代表实测耗时或识别效果。录制工具与资源不属于本次界面交付
- **核心能力**：交替左右大行（偶数行翻转，形成来回的阅读路径），
  插图是纯 CSS 画的（OCR 识别 / 交叉比对 / 规则命中 / 存档报告），
  不引图片资源。**不套卡片**，靠大留白 + 底部细分隔线区分条目
- **并排比对预览**：三份单证并置，冲突字段只在那份不一致的文件上高亮
  （左色条 + 底色），比"字段 × 文件"的表格更像"比对"
- **滚动揭示**：`.reveal` 区块进入视口时上浮淡入。**默认可见**——
  隐藏样式只由 JS 给"确实在视口下方"的元素加 `.reveal--armed` 才生效。
  反过来做（默认隐藏等 JS 揭示）一旦观察器漏触发（快速跳转滚动、打印、
  无 JS），内容就永久隐形了。动画只能是增强，不能是内容可见的前提
- **mock 演示场景直达**：仅示例数据模式渲染；按「常规单证 / EDI 报文」分组，
  每张卡带一句说明和预期结果徽章（文案在 `state/scenarios.js`）；点场景卡设定场景后跳上传页，
  由上传页挂载时自动提交一次检查。全站持续显示“示例数据”说明；任务从排队逐步
  推进到样例终态，失败文件不能呈现为已抽取，禁用存储时仍能完成流程

导航约定：首页隐藏顶栏页签与底部标签（入口页减少干扰）；品牌区做成可点按钮
（含一枚纯 CSS 画的"单证方章"标识），任何页面可点回首页。

**不做最近任务列表**：首页只呈现当前任务。真实任务完成后 URL 保存任务编号，
刷新时向后端重新读取并恢复报告；示例结果和本地 File 对象不持久化。不能由当前
任务推断或构造历史列表。

**不做装饰性循环动效**：首页曾加过一条扫描线扫过单证叠放（扫到冲突行时点亮、
旗标落下）。它读起来像"一直在循环播放"，且让插图在多数时刻处于中间态——
静态截图与视频抽帧容易拍到半截状态。现在冲突行与旗标常驻，只保留散开一次
的入场动画与滚动揭示。

### 路由与导航

导航由 vue-router 承载（hash 模式——静态托管没有 history rewrite 能力，
hash 模式刷新不 404）：

- **页签的排列与文案来自 `App.vue` 的 `PAGES`**（导航 = 上传 / 差异 / 报告）。
  `meta.label` 目前无人读取；`meta.order` 只承载纸张层叠切换的前进/后退方向
  （首页 order 最小 -1，去向任何页都算前进）。
- **评测页不进导航**：它不依赖任务状态，是"关于系统本身"的页面，
  放进流程页序会暗示它属于「上传 → 比对 → 报告」这条线。入口只有首页 Hero 的
  「查看评测数据」，退出靠品牌按钮或浏览器后退——与首页同款处理。
  因此 `showNav` 对首页与评测页都不渲染导航壳（顶栏页签与底部标签同源）。
  评测页保留 `order: 3`：首页→评测算前进、评测→首页算后退。
- 守卫重定向：没有任务时差异页和报告页没有内容可显示，`beforeEach`
  统一把 `/diff`、`/report` 重定向回 `/upload`（tab 禁用只是 UI 层拦截，
  直接改 hash 仍能进来，守卫是第二道防线）。
- 导航壳不渲染时 `updateIndicator` 找不到 `.tab.active`，走淡出分支，
  指示条元素随 nav 一起从 DOM 消失，不留悬空的条。ResizeObserver 需随
  `tabsRef` 出现再挂（否则直接从 `#/eval` 打开时永远不会挂上，
  只在"尺寸没变但页签宽度变了"时量不到）。
- 跨页状态（task、上传表单、筛选、评测缓存等）的单一来源是
  `src/state/session.js`，App.vue 只做 provide 转发，页面 inject 使用。

### 扫描件预检提示（上传页）

PDF 文本层预检测命中的行内标记（`.scan-warn`）与汇总提示条：

- 位置：文件名右侧行内（`⚠ 疑似扫描件`），warning 边框 + 底色 + 文字
- `cursor: help` + `title` 放完整说明；预检测为本地启发式判断，措辞使用「疑似 / 可能」，提示将通过 OCR 识别，不阻止提交

## 状态层级

页面随切页重挂载，**页面级 ref 切页即丢**。需要在页面间存活的状态一律提升到
App 层（provide/inject）：检查任务（task）、上传页表单（文件列表/目的国/备注/
扫描件警告）、评测数据缓存。任务还在、输入却丢了，就是层级放错的信号。

跨页状态的单一来源是 `src/state/session.js`（ref 本体都在那里定义），
App.vue 只做 provide 转发，不在 App 里另建 ref。

### 「需关注」口径

一条比对是否需要人工复核，由 `utils/needsReview.js` 的 `needsReview` 统一判定：
比对状态 ∈ {CONFLICT, MISSING_IN_SOME, NOT_CHECKED, UNRECOGNIZED}，或任一取值的
`field_status === 'LOW_CONFIDENCE'`（徽章「请核对」）。MATCH 比对也可能含低可信
取值——只看状态集合会把它们漏到「全部」筛选里。差异页筛选与计数、报告页问题
条目、顶栏差异页角标三处共用这一函数，**不允许各页面再写等价判断**。

## 约束

- 响应式布局：桌面端双栏/表格与对照双视图；窄屏（≤640px）自动切换为底部导航栏与单列对照视图
- 设计目标：所有交互元素支持键盘操作，focus-visible 样式明显；新增交互需实测
- 设计目标：普通文本对比度达到 WCAG AA（4.5:1），需逐项检查，不宣称已全面认证
- 无 UI 组件库；产物体积以当前构建输出为准，不固定历史数值
