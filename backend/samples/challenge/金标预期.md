# 格式与语言挑战样例：金标预期

使用 `python tools/make_challenge_samples.py` 重新生成 PDF/PNG，使用
`python tools/run_challenge.py` 上传文本层 PDF 并将结果写入 `.out/challenge/`。
这些是**合成样例**；PNG 仅验证未配置 OCR 时明确失败，尚不能证明图片识别质量。

| 样例 | 输入差异 | 应有结果 |
|---|---|---|
| `09_us_format_mixed` | 中文发票、英文装箱单及提单；`2026-10-08`、`08.10.2026`、`OCT 8, 2026` | 三份**装运日期**均为 `2026-10-08`，`MATCH`；重量 2400，0 个 `CONFLICT` |
| `10_de_ambiguity_conflict` | `2.400,00 KGS` 对 `2,400.00 KGS` | 毛重均为 2400，`MATCH` |
| `10_de_ambiguity_conflict` | `10/05/2026` 缺地区约定 | `shipment_date=NORMALIZE_FAILED`，不能猜成 5 月 10 日或 10 月 5 日；其它明确日期可对齐 |
| `10_de_ambiguity_conflict` | `2026年10月05日` | 归一为 `2026-10-05` |
| `10_de_ambiguity_conflict` | `US$12,500.00` 对 `EUR 12,500.00` | 金额均为 12500，但币种冲突；`total_amount` 与 `currency` 均应报 `CONFLICT` |
| `10_de_ambiguity_conflict` | 数量 9800 对 9600 | 真实 `CONFLICT` |
| `11_de_multiitem_mixed` | 四个商品、两份文件行序不同 | 4 个行组，跨文件按货号对齐；品名级数量与重量分别比较 |
| `11_de_multiitem_mixed` | 中文“陶瓷 餐具 16PC 蓝”对英文 `CERAMIC TABLEWARE 16PC BLUE` | 该品名描述 `MATCH` |
| `11_de_multiitem_mixed` | `BEIGE` 对 `BLUE` | 对应品名描述 `CONFLICT` |
| `11_de_multiitem_mixed` | 发票合计 `9600 PCS`、`AMOUNT USD 13,500.00` | 票级数量 9600、金额 13500；发货人不能被误抽为货物描述 |
| PNG 探针 | 未配置识别服务 | `FAILED`，有 `DOC_PARSE_FAILED`，不能生成虚假比对结论 |

注意：`ISSUE DATE` 是单证签发日期，不能与装运日期混用。09、10 的装箱单特意写作
`SHIPMENT DATE`，使日期比较有业务意义。提单中缺体积等字段仍可能按临时单证字段表
出现 `MISSING_IN_SOME`；这与“0 个冲突”是不同指标，需等 C 的正式适用表确认。

以上为**预期**，实际验收应检查 `.out/challenge/` 的输出；不可把某次实跑结果直接当金标。
