# 合成物流 EDIFACT 样本集（D.96A）

本目录包含 **12 个测试场景、共 23 份 `.edi` 合成报文**及配套字段预期 [`expected.json`](expected.json)，遵循 `UN/EDIFACT D.96A` 标准的 `INVOIC`（商业发票）与 `DESADV`（发运通知）选定子集，供 EDI 解析器研发与端到端联调使用。

> 所有公司名称、地址、单据编号与交易数据均为合成测试数据，仅用于系统验证。

---

## 1. 场景目录清单

| 场景目录 | 文件数 | 场景设计与验证目标 |
|---|---:|---|
| `01_consistent` | 2 | 单商品数量、包装件数、毛净重、HS 编码完全一致；金额仅由商业发票提供 |
| `02_quantity_conflict` | 2 | 商品数量分别为 `2400 PCE` 与 `2380 PCE`（数量不一致），包装件数均为 `100 CT` |
| `03_net_gross_swapped` | 2 | 发运通知中净重与毛重数值颠倒，检验语法合法但业务数值冲突的检出能力 |
| `04_amount_conflict` | 3 | 发票原件、副本与发运通知并存；单价（`2.00` / `2.10`）与总金额（`4800.00` / `5040.00`）不一致 |
| `05_currency_conflict` | 3 | 发票原件与副本金额数值相同，但申报币种分别为 `USD` 与 `EUR` |
| `06_missing_hs_currency` | 2 | 发票缺失 HS 编码与币种段，检验缺失状态保留（不默认补 `USD`） |
| `07_multiitem_reordered` | 2 | 3 个商品在发票与发运通知中行序不同，按商品货号（`LIN` / `SA`）准确关联 |
| `08_release_characters` | 2 | 商品描述包含 `+`、`:`、`?`、`'` 等 EDIFACT 保留字符与 `?` 转义序列 |
| `09_decimal_comma_compact` | 2 | `UNA` 服务串指定逗号作为十进制小数点，且段间无换行符紧凑排列 |
| `10_multi_message` | 1 | 单个 `UNB/UNZ` 交换信封内包含 2 条报文（`INVOIC` + `DESADV`） |
| `11_bad_unt_count` | 1 | **异常负例**：`UNT` 段计数与实际段数不符，预期解析器显式报错拒绝 |
| `12_truncated` | 1 | **异常负例**：报文截断缺失 `UNT` 与 `UNZ` 尾段，预期显式报错拒绝 |

## 2. 核心段与字段映射规范

| 业务字段 | EDIFACT 段与限定符 | 映射说明 |
|---|---|---|
| 单证编号 | `BGM+380`（发票） / `BGM+351`（发运通知） | 各单证自身编号；`DESADV` 通过 `RFF+IV` 引用关联发票号 |
| 签发日期 / 装运日期 | `DTM+137` / `DTM+11`（格式 `102`） | 严格区分单证签发日期与实际装运日期 |
| 商品货号 / HS 编码 | `LIN`（`SA`） / `PIA`（`HS`） | 用于跨报文商品行对齐与归类核对 |
| 商品描述 | `IMD+F` | 解析时还原 `?` 转义字符，原件预览保留原始字节 |
| 商品数量 | `QTY+47`（发票） / `QTY+12`（发运），单位 `PCE` | 归一映射为项目标准单位 `PCS` |
| 包装件数 | `PAC`（类型 `CT`） | 归一映射为 `CARTON` |
| 毛重 / 净重 / 体积 | `MEA`（`AAD`/`AAC` 整票，`AAE`/`AAL` 行级，`AAW` 体积） | 重量单位 `KGM` 映射为 `KGS`，体积 `MTQ` 映射为 `CBM` |
| 行金额 / 整票总金额 / 单价 | `MOA+203` / `MOA+77` / `PRI+AAA` | 配合 `CUX+2:<币种>:4` 提取申报币种 |

## 3. 重新生成样本

如需在临时目录重新生成全部 23 份报文与 `expected.json`（仅依赖 Python 标准库）：

```sh
edi_output_dir=$(mktemp -d)
python backend/tools/make_edi_samples.py --output "$edi_output_dir"
```
